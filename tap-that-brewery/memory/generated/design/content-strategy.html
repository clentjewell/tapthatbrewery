Why a content system, not a content calendar

Tap That Brewery's buying cycle is the design constraint: ~60% of buyers take up to three months to commit, 40% longer. Today that consideration window is "nurtured by memory" (D05) — the in-venue pathway (taste → demo → giveaway → 50% close) has no digital equivalent. Content is that equivalent. It must serve social (#41), the website, and email/SMS lifecycle from one production effort, because the whole machine runs on Raef at ~70% capacity plus defined Jewell support.

Repurposing flows — one shoot, many assets

The monthly batch shoot (~2–3 hrs, venue + one customer location) is the entire production engine. Nothing is shot for a single use.

Flow A — build showcase: customer install shoot → 1 Reel (kudos pillar) → 3 stills (feed + stories) → testimonial pull-quote (website + Google reviews prompt) → ad creative candidate → space/fit guide example → UGC seed (customer reposts, earns Tap Tokens).

Flow B — brewery floor: 30 min with Chris + the Kegged & Ready board → 1 Reel → tasting-notes page update → "what's pouring" email block → wholesale one-pager imagery (#44).

Flow C — giveaway cycle: launch film → countdown story frames → entrant prompts → winner install (= next month's Flow A) → 50%-close creative → case-study numbers for the Gate 2 story.

Flow D — help article: one written guide → carousel summary → lifecycle email link → FAQ schema on the website (#43 local SEO).
